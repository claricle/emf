= emf: parser for WMF, EMF, and EMF+ metafiles

`emf` is a clean-room Ruby parser with an optional Rust native backend for the three Microsoft Windows
metafile formats:

* **WMF** — Windows Metafile (see MS-WMF, kaitai `wmf.ksy`)
* **EMF** — Enhanced Metafile (see MS-EMF)
* **EMF+** — Enhanced Metafile Plus (see MS-EMFPLUS; embedded in EMF
  via `EMR_COMMENT` records)

It reads binary input into an OOP domain model and serialises the model
back to binary. It is the parsing half of the upcoming `emfsvg` gem
(EMF <-> SVG transformation). It replaces the FFI-based `emf2svg-ruby`
wrapper around the GPLv2 `libemf2svg` C library.

== Status

* **EMF**: parsing, mutable wire records and binary serialization are implemented.
* **EMF+**: raw carrier payloads (`Metafile#emf_plus`) and a typed stream view
  (`Metafile#emf_plus_stream`) are implemented.
* **WMF**: standard and placeable headers, records and binary serialization
  are implemented.
* **Native backend**: Rust decoding and a Ruby adapter are implemented; final-source
  native qualification and installed platform qualification remain open.
* **Qualification**: implementation does not imply complete format coverage or
  release readiness. See link:TODO.plan/10-progress.md[delivery progress] and
  link:TODO.plan/09-format-extension.md[format extension acceptance].

== Installation

Add to your Gemfile:

  gem "emf", "~> 0.1"

Or install directly:

  gem install emf

Requires Ruby >= 3.1.

== Backend selection

The public `Emf.parse`, `Emf.parse_file` and `Emf.serialize` APIs use
`EMF_BACKEND` at call time:

[cols="1,3",options="header"]
|===
|Value |Behavior
|`auto` (default) |Use the native backend when available; fall back to Ruby if native setup raises `Emf::Native::Unavailable`.
|`ruby` |Use Ruby directly, without loading the native library.
|`native` |Require the native backend; unavailable setup raises `Emf::Native::Unavailable`.
|===

Other values raise `ArgumentError`. A parsing or serialization error after
backend selection propagates to the caller; it is not retried using Ruby.
Both backends return the existing Ruby model and use the Ruby binary writers
for serialization, including mutable wire records.

For example, to explicitly use Ruby:

  EMF_BACKEND=ruby ruby -remf -e 'p Emf.parse_file(ARGV.fetch(0)).format' image.emf

Native loading uses a packaged platform manifest when present. For development
with an existing compatible library, `EMF_NATIVE_LIBRARY` overrides discovery:

  EMF_BACKEND=native EMF_NATIVE_LIBRARY=/absolute/path/to/libemf_ffi.dylib ruby -remf -e 'p Emf.parse_file(ARGV.fetch(0)).format' image.emf

Use the appropriate shared-library filename for the platform. An empty override
makes native loading unavailable. Native installation and platform support must
be qualified using link:TODO.plan/08-platform-delivery.md[the delivery checks];
the source implementation alone does not establish an available platform gem.

== Synopsis

  require "emf"

  # Parse from bytes or a file path
  metafile = Emf.parse_file("image.emf")
  metafile.format         # => :emf or :emf_plus
  metafile.records.length # => 3538
  metafile.errors.empty?  # => true (no parse errors)

  # Walk records with a visitor
  stats = Emf::Visitors::Stats.new.visit_all(metafile)
  puts stats.to_s

  # Serialise the model back to binary
  bytes = Emf.serialize(metafile)

== Command-line tool

  emf version                  Print version
  emf info FILE                Header summary + record counts
  emf dump FILE                Record-by-record dump
  emf stats FILE               Record-type histogram
  emf validate FILE            Parse + report errors (exit 0 ok, 1 invalid)
  emf round-trip FILE [--out]  Re-serialize after parse, compare or write

== Architecture

Three layers, kept strictly separate (MECE):

  binary bytes --[bindata]--> Emr::Binary::*Record (byte-faithful)
                                     |
                              Record.from_wire
                                     v
                                Model::*Record (semantic OOP, immutable)
                                     |
                              Record#to_wire
                                     v
                          Emr::Binary::*Record --[bindata]--> binary bytes

* **Wire layer** (`Emf::Emr::Binary::*`): one bindata class per EMR record
  type, declared by spec. Pure data, no behaviour. Symmetric read/write.
* **Domain layer** (`Emf::Model::*`): immutable value objects with
  `attr_reader`, value equality, `accept(visitor)`, `from_wire`, `to_wire`.
* **Visitor pattern** (`Emf::Model::Visitor`): consumers subclass the base
  and override only the `visit_*` methods they care about. Adding a record
  type touches the record's own file plus three lines in `records.rb`
  (autoload + TYPE_TO_NAME + the file itself) -- no central switch.

=== Constraints honoured throughout

* No `require_relative` and no `require` of internal paths in `lib/` --
  everything autoloads via the parent-namespace file pattern.
* No `double()` in specs -- real instances only.
* No `send` to private methods, no `instance_variable_set`/`get`, no
  `respond_to?` for type checks.
* No AI attribution in any commit. All changes go through PRs.

See `docs/architecture.adoc` and `docs/format_notes.adoc` for the deep
dive, and link:TODO.plan/10-progress.md[delivery progress] for implementation status.

=== Reference documentation

The Microsoft specifications are checked in at `reference-docs/` as both
the original `.docx` files and per-chapter GFM markdown under
`reference-docs/<spec>/`. The conversion script is
`scripts/convert_docs.rb` (rubyzip + nokogiri). Re-run when the spec
revision bumps.

== Development

  git clone https://github.com/claricle/emf
  cd emf
  bundle install
  bundle exec rspec       # fixture and unit checks
  bundle exec rubocop     # clean

The round-trip harness in `spec/emf/round_trip_spec.rb` is the strongest
correctness signal: it walks every non-corrupted fixture and asserts
byte-identical parse -> serialise -> parse.
