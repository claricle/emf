## Context

Continuous integration must run specs, rubocop, and the doc converter on every push and PR. Release must be a tag-triggered manual flow (NEVER push tags automatically per global rule).

## Outcomes

- `.github/workflows/test.yml` runs on push/PR:
  - Matrix: Ruby 3.1, 3.2, 3.3 on ubuntu-latest and macos-latest.
  - Steps: checkout, setup Ruby, `bundle install`, `bundle exec rspec`, `bundle exec rubocop`.
  - Caches bundler.
- `.github/workflows/docs.yml` runs on push to `main` (only if `reference-docs/[MS-*.docx` changed):
  - Runs `scripts/convert_docs.rb` for each spec.
  - Commits the converted output (uses `gitleaks`-safe bot account, no AI attribution).
- `.github/workflows/release.yml` runs on tag push `v*`:
  - Builds the gem (`bundle exec rake build`).
  - Publishes to rubygems.org using `EMF_RUBYGEMS_API_KEY` secret.
  - **Never triggers on main. Never auto-tags.**
- Branch protection on `main` is documented in CONTRIBUTING (require PR review).

## Files

```
.github/workflows/test.yml
.github/workflows/docs.yml
.github/workflows/release.yml
```

## Verification

- Push to a feature branch triggers `test.yml`.
- PR to main triggers `test.yml`.
- Tag `v0.1.0` triggers `release.yml` (manually created by user, NOT by Claude).

## Constraints (global rules)

- No `Co-authored-by` trailers for AI in any commit message produced by the workflow.
- No auto-merge to main.
- No auto-tagging.

## Done when

- [ ] `test.yml` is green on a sample PR.
- [ ] `docs.yml` runs the converter and commits output.
- [ ] `release.yml` is gated on tag push, not on main commits.
- [ ] No AI attribution anywhere.
